# Computer Science (Form 1): question-type audit

Audit only, no content written. Source: `data/spine/computer-science.json` (55 rows: 42 teachable, 13 reuse). Generated by `python tools/audit/build_audit.py`; the judgements are in `tools/audit/audit_data.py`.

**Classes** (one per row, by the main kind of practice the row allows):

- **C** computed: code verifies? yes: code computes the answer
- **F** fact table: code verifies? yes: against an authored table
- **A** authored: code verifies? yes: against an authored key
- **X** paper-only: code verifies? no: self-check against a model answer
- **D** deferred: code verifies? no: needs audio or equipment

Question types: `TPL` templated (computed); `TBL` templated from a fact table; `MCQ` authored MCQ; `CLZ` cloze; `ORD` ordering; `MAT` matching; `MAT(sort)` matching (sort into groups); `LBL` labelling; `SPOT` spot the error; `PAP` paper-only.

Assets: `d:` drawn SVG diagram, `m:` drawn SVG map, `g:` drawn by code from the question data (no file; answers stay computed).

## Engine gaps

- **Mini interpreter** for pseudocode tracing: variables, assignment, IF, a counted loop, OUTPUT. It can reuse `src/engine/expr.js` (no eval).
- **Sequence generator** for pattern recognition (number and shape rules).
- **Spreadsheet evaluator**: cell references, ranges, SUM, AVERAGE, MIN, MAX on top of `expr.js`.
- **Folder-tree simulator** (create, move, copy, rename, path) and **URL parser**.
- **Touch-gesture drill** (tap, double tap, long press, drag), checked by the app itself.
- **Block editor:** Blockly is roughly 700 KB minified, a third of the whole 2 MB budget. A tiny custom block editor (sequence, repeat, if; about 10 blocks) is possible but is real engine work. Decision for Dion: build small, or keep row 35 on paper.
- **Labelling**, **matching**, **sort into groups**, **fact-table templates**.

## Risks and notes

- **AI rows (4–6, 26–27)** date quickly: keep them about ideas (what a prompt is, checking answers, privacy), not about named products.
- **Ethics rows (29–31)** are judgement: write clear-cut scenarios so the key is not arguable.
